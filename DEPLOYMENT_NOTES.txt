Hub FinProms — Deployment Notes
================================
Last updated: 2026-09-15

Repos
1. ARCHITECTURE (IMPORTANT)
================================================================================
- Backend and frontend are SEPARATE repos:
  - Backend:  Desktop/hub-finproms-backend
  - Frontend: Desktop/hub-finproms-frontend
- Shared hub and every white-label hub use the SAME codebase.
- Each hub has its OWN database (do NOT share DBs between hubs).
- HUB_SLUG in .env identifies which hub this deploy is.
- Power Admin on the SHARED hub is the control plane (hub registry + wiring).

Option B (used for both shared + myhub):
  Frontend:  https://<domain>/
  API:       https://<domain>/api/...
  Laravel lives in: public_html/api/
  Document traffic for /api goes to: api/public/index.php via .htaccess

2. SHARED HUB — https://sharedhub.fin-proms.com
================================================================================

cPanel user example: sharedhubfp

Folders:
  public_html/
    index.html, assets/, .htaccess   ← frontend build
    api/                             ← Laravel backend

GitHub Actions FTP (IMPORTANT):
  The FTP account Directory in cPanel MUST be:
    /home/<cPanelUser>/public_html
  If it is set to something like:
    /home/<cPanelUser>/sharedhub.fin-proms.com/ftpaccount
  builds upload "successfully" but the live site never updates.
  Fix: cPanel → FTP Accounts → Change Directory → public_html
  Then re-run the frontend deploy workflow.

.env essentials (public_html/api/.env):
  APP_ENV=production
  APP_DEBUG=false
  APP_URL=https://sharedhub.fin-proms.com
  FRONTEND_URL=https://sharedhub.fin-proms.com
  SANCTUM_STATEFUL_DOMAINS=sharedhub.fin-proms.com
  HUB_SLUG=shared
  DB_HOST=localhost
  DB_DATABASE=<shared cPanel DB name>
  DB_USERNAME=<shared cPanel DB user>
  DB_PASSWORD=<password>
  FILESYSTEM_PUBLIC_URL=https://sharedhub.fin-proms.com/api/media
  WEBSITE_COMPLIANCE_HUB_API_URL=https://sharedhub.fin-proms.com/api
  WEBSITE_COMPLIANCE_UPLOADS_ORIGIN=https://sharedhub.fin-proms.com/api
  SCHEDULER_SECRET=<long random secret>
  BANK_TRANSFER_ENABLED=false

  WARNING: Do NOT copy .env.example over production .env.
  WARNING: Do NOT run php artisan key:generate if APP_KEY already exists.
  WARNING: Do NOT run php artisan db:seed --force on production
           (it resets seeded admin passwords to "password").

After a zip replace, run these in ~/public_html/api:
  composer install --no-dev --optimize-autoloader
  mkdir -p storage/framework/cache storage/framework/sessions storage/framework/views storage/logs bootstrap/cache
  chmod -R 775 storage bootstrap/cache
  php artisan config:clear
  php artisan cache:clear
  php artisan route:clear

.env must keep the EXISTING APP_KEY=base64:... from the old deploy.
Add if missing:
  SESSION_DRIVER=file
  CACHE_STORE=file
  QUEUE_CONNECTION=sync

Then:
  php artisan config:cache

If login still fails, check:
  tail -n 80 storage/logs/laravel.log

Frontend:
  - Build from hub-finproms-frontend with:
      VITE_API_URL=https://sharedhub.fin-proms.com/api
    (.env.production or: npm run build / build:shared)
  - Upload dist (or dist-shared) contents into public_html
  - Keep the api/ folder

Smoke tests:
  https://sharedhub.fin-proms.com/api/hub
  https://sharedhub.fin-proms.com/

4. public_html/.htaccess (BOTH hubs — Option B)
================================================================================
Copy this into public_html/.htaccess (domain root, next to frontend):

<IfModule mod_rewrite.c>
  RewriteEngine On

  # cPanel CGI often drops Authorization; without this, login 200 then /auth/me 401
  RewriteCond %{HTTP:Authorization} .
  RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]
  SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1

  # Already the real file path — stop here (prevents rewrite loops / 500)
  RewriteRule ^api/storage/app/public/ - [L]

  # Map public asset URLs to the real disk folder under the Laravel app
  RewriteRule ^storage/(.*)$ api/storage/app/public/$1 [L]
  RewriteRule ^api/storage/(.*)$ api/storage/app/public/$1 [L]

  # Laravel API
  RewriteCond %{REQUEST_URI} ^/api
  RewriteRule ^api(?:/(.*))?$ api/public/index.php [L,QSA]

  # Frontend SPA
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule ^ index.html [L]
</IfModule>

5. LOGOS / FAVICONS (common production issue)
================================================================================
- Uploads are stored in: api/storage/app/public/hubs/logos|favicons/
- On cPanel, public/storage symlink is often broken after zip upload.
- Prefer FILESYSTEM_PUBLIC_URL=https://<domain>/api/media
  (served by PublicStorageController — no symlink required)
- Also keep .htaccess storage rules above as backup.
- After changing .env:
    php artisan config:clear
    php artisan config:cache

- Branding edited from the SHARED hub (hub switcher) uploads files onto
  shared storage. White-label sync pushes absolute shared media URLs into
  the tenant hubs row (not relative paths). Shared must have a correct
  FILESYSTEM_PUBLIC_URL / APP_URL so those URLs are publicly reachable.
- After deploying this sync fix, re-save logo/favicon once from Shared so
  the white-label DB gets absolute URLs (or wait ≤60s for hub cache).

Test logo URL examples:
  https://sharedhub.fin-proms.com/api/media/hubs/logos/<filename>
  (white-label site may reference the shared URL above after control-plane sync)

6. MIGRATION GOTCHA (MySQL index name too long)
================================================================================
If migrate fails on social_media_compliance_requests with:
  Identifier name ... is too long

Use the fixed migration files (short index names):
  database/migrations/2026_09_12_180100_create_compliance_requests_tables.php
  database/migrations/2026_09_12_210000_create_general_compliance_tables_and_capabilities.php

If a half-created table exists:
  DROP TABLE IF EXISTS social_media_compliance_request_versions;
  DROP TABLE IF EXISTS social_media_compliance_requests;
Then:
  php artisan migrate --force
  php artisan db:seed --force

8. WEBSITE COMPLIANCE — TEMPLATE4 SHOWCASE (myhub)
================================================================================
template4 is owned by the myhub white-label deploy only.
Do NOT seed or host it on sharedhub — shared DB must not store template4 rows.

Deploy Desktop/template4-showcase to:
  https://myhub.fin-proms.com/template4/

----- A) REMOVE from sharedhub (if previously deployed by mistake) -----
1. cPanel (sharedhub): delete folder public_html/template4/ entirely
2. On shared Laravel API:
     cd ~/public_html/api
     php artisan wc:purge-foreign-templates
   Or:
     php artisan db:seed --class=WebsiteComplianceTemplateSeeder --force
   (with HUB_SLUG=shared this deletes template4 + related wc_sections / requests)

----- B) Deploy to myhub -----
Local prepare:
  cd Desktop/template4-showcase
  # config.js DEPLOYMENT_MODE=showcase, UPLOADS_ORIGIN=https://myhub.fin-proms.com/api
  npm install
  npm run build

cPanel (myhub) upload:
  Create folder: public_html/template4/
  Upload ALL of dist/* into that folder (index.html, assets/, api.php,
  includes/, data/, .htaccess, cpanel-config.php, etc.)

Edit public_html/template4/cpanel-config.php (showcase mode):
  DEPLOYMENT_MODE = showcase
  DB_*            = SAME as myhub public_html/api/.env (myhub Laravel DB)
  ADVISOR_ID      = null
  UPLOADS_ORIGIN  = https://myhub.fin-proms.com/api
  SITE_URL        = https://myhub.fin-proms.com/template4
  LARAVEL_API_URL = https://myhub.fin-proms.com/api

Laravel myhub .env:
  HUB_SLUG=myhub
  TEMPLATE_PREVIEW_BASE_URL=https://myhub.fin-proms.com
  WEBSITE_COMPLIANCE_HUB_API_URL=https://myhub.fin-proms.com/api
  WEBSITE_COMPLIANCE_UPLOADS_ORIGIN=https://myhub.fin-proms.com/api

After uploading a new backend (or after changing template4-dummy-content.json),
refresh showcase rows in the MYHUB DB only:

  cd ~/public_html/api
  php artisan wc:seed-showcase-sections
  # or: php artisan db:seed --class=WebsiteComplianceTemplateSeeder --force

This overwrites wc_templates.dummy_content + wc_sections where advisor_id IS NULL
from database/data/website-compliance/template4-dummy-content.json
(Hero per-slide content, What we do boxes, etc.).

Hub ownership (config/services.php hub_showcase_templates):
  myhub  → template4
  shared → (none)
Override per deploy with WC_SHOWCASE_TEMPLATES=slug1,slug2 if needed.

Power Admin on sharedhub with hub switcher set to myhub reads/writes myhub's
wc_* tables over the remote DB credentials on the hub registry. Ensure myhub
has Remote database configured in Power Admin → Hub deploy wiring.

Update preview URL in DB (or re-seed WC templates):
  UPDATE wc_templates SET preview_url='https://myhub.fin-proms.com/template4/'
  WHERE slug='template4';

Smoke tests:
  https://myhub.fin-proms.com/template4/
  https://myhub.fin-proms.com/template4/api.php
  (api.php should report deployment_mode=showcase, db_name = myhub DB)

Root public_html/.htaccess already skips real directories (!-d), so /template4/
will not be swallowed by the SPA once the folder exists.

NOTE: Advisor live sites use a SEPARATE copy + local DB + DEPLOYMENT_MODE=advisor.
Never copy showcase cpanel-config.php onto an advisor cPanel.
