Hub FinProms — Deployment Notes
================================
Last updated: 2026-09-29

================================================================================
1. ARCHITECTURE (IMPORTANT)
================================================================================
- Backend and frontend are SEPARATE repos:
  - Backend:  Desktop/hub-finproms-backend
  - Frontend: Desktop/hub-finproms-frontend
- ONE codebase for three instance types:
  A) Central Hub Controller — control plane ONLY (hub registry, Power Admin,
     remote hub switcher). Not a member content catalog.
  B) Shared hub(s) — content hubs (many allowed; each own DB + slug)
  C) White-labelled hub(s) — private client content hubs
- Each instance has its OWN database (do NOT share DBs between hubs).
- HUB_SLUG identifies this deploy; set HUB_TYPE=shared|white_label|central when needed.
- Power Admin / hub registry live ONLY on Central (HUB_IS_CONTROL_PLANE=true).

Option B (used for central + shared + white-label):
  Frontend:  https://<domain>/
  API:       https://<domain>/api/...
  Laravel lives in: public_html/api/
  Document traffic for /api goes to: api/public/index.php via .htaccess


================================================================================
1A. CENTRAL HUB CONTROLLER (deploy this for the control plane)
================================================================================
Deploy a NEW cPanel for Central. Central holds the hub registry for ALL Shared
and White-label hubs. Shared content DBs must NOT keep that registry.

Example domain: https://central.fin-proms.com  (use your real domain)

Backend .env (public_html/api/.env):
  HUB_SLUG=central
  HUB_TYPE=central
  HUB_IS_CONTROL_PLANE=true
  HUB_PROMOTE_TO_CENTRAL=true
  APP_URL=https://central.fin-proms.com
  FRONTEND_URL=https://central.fin-proms.com
  SANCTUM_STATEFUL_DOMAINS=central.fin-proms.com
  DB_* = Central's OWN database
  FILESYSTEM_PUBLIC_URL=https://central.fin-proms.com/api/media

First install on Central:
  composer install --no-dev --optimize-autoloader
  php artisan migrate --force
  php artisan db:seed --force   # ONLY on empty Central DB
  php artisan config:cache

Frontend:
  npm run build:central
  Upload dist-central/ into public_html
  (.env.central → VITE_API_URL pointing at Central API)

After Central is up:
  1) Log in as Power Admin → Hubs → register each Shared + White-label
  2) Set frontend_url + remote DB credentials (Wiring ready)
  3) On each content hub: php artisan hub:strip-control-plane --force
  4) On each Shared .env: HUB_IS_CONTROL_PLANE=false and HUB_TYPE=shared

CODE STATUS: backend + frontend support for Central is in place. Ready to deploy
Central when you have a cPanel + empty DB + domain and have updated .env.central.

4. public_html/.htaccess (BOTH hubs â€” Option B)
================================================================================
Copy this into public_html/.htaccess (domain root, next to frontend):

<IfModule mod_rewrite.c>
  RewriteEngine On

  # cPanel CGI often drops Authorization; without this, login 200 then /auth/me 401
  RewriteCond %{HTTP:Authorization} .
  RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]
  SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1

  # Already the real file path â€” stop here (prevents rewrite loops / 500)
  RewriteRule ^api/storage/app/public/ - [L]

  # Map public asset URLs to the real disk folder under the Laravel app
  RewriteRule ^storage/(.*)$ api/storage/app/public/$1 [L]
  RewriteRule ^api/storage/(.*)$ api/storage/app/public/$1 [L]

  # Laravel API
  RewriteCond %{REQUEST_URI} ^/api
  RewriteRule ^api(?:/(.*))?$ api/public/index.php [L,QSA]

  # Frontend SPA
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule ^ index.html [L]
</IfModule>

5. LOGOS / FAVICONS (common production issue)
================================================================================
- Uploads are stored in: api/storage/app/public/hubs/logos|favicons/
- On cPanel, public/storage symlink is often broken after zip upload.
- Prefer FILESYSTEM_PUBLIC_URL=https://<domain>/api/media
  (served by PublicStorageController â€” no symlink required)
- Also keep .htaccess storage rules above as backup.
- After changing .env:
    php artisan config:clear
    php artisan config:cache

- Branding edited from the SHARED hub (hub switcher) uploads files onto
  shared storage. White-label sync pushes absolute shared media URLs into
  the tenant hubs row (not relative paths). Shared must have a correct
  FILESYSTEM_PUBLIC_URL / APP_URL so those URLs are publicly reachable.
- After deploying this sync fix, re-save logo/favicon once from Shared so
  the white-label DB gets absolute URLs (or wait â‰¤60s for hub cache).

Test logo URL examples:
  https://sharedhub.fin-proms.com/api/media/hubs/logos/<filename>
  (white-label site may reference the shared URL above after control-plane sync)

9. SCHEDULER (WC publish + hub backups)
================================================================================
cPanel Cron (every minute), on EVERY hub (Central + Shared + White-label):
  cd /home/<cpanel_user>/public_html/api && php artisan schedule:run >> /dev/null 2>&1

This runs:
  - wc:publish-scheduled (Website Compliance)
  - hubs:run-due-backups (per-hub backup schedule from Central Power Admin)

Hub backups (dual store):
  - Enable schedule per hub on Central -> Hub detail -> Backups
    (or Platform -> Hub backups for the Control hub selection)
  - Content hubs: set api_url in deploy wiring (.../api) so Central can trigger
    backup/restore callbacks; optional CENTRAL_API_URL on content hubs for
    independent upload when their own cron runs
  - Archives: content hubs use storage/app/backups/{slug}/ (local) + upload to
    Central storage/app/backups/central/{slug}/. Central itself keeps one copy
    under storage/app/backups/central/{slug}/ only.
  - After deploy on all hubs: php artisan migrate
  - PHP zip: prefer enabling the php-zip extension on every hub
    (cPanel → Select PHP Version → Extensions → zip). Backups also fall back
    to the system `zip`/`unzip` binaries when the extension is missing.

Or HTTP (WC only):
  GET https://<domain>/api/website-compliance/scheduler/publish-scheduled?key=<SCHEDULER_SECRET>
